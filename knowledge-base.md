# Multiplayer Bingo Game

A real-time multiplayer Bingo game built with Node.js, Express, Socket.IO, and Tailwind CSS.

## Features

- **Real-time multiplayer gameplay** - Two players can play simultaneously
- **Custom grid setup** - Players create their own 5x5 Bingo grids
- **Turn-based gameplay** - Players take turns selecting numbers
- **Live game state sync** - All actions are synchronized in real-time
- **Winner detection** - Automatic detection of winning patterns (rows, columns, diagonals)
- **Session leaderboard** - Track wins across multiple games
- **Responsive design** - Works on desktop and mobile devices

## Installation

1. **Clone or download the project**
2. **Install dependencies:**
   ```bash

   ```



## How to Play

1. **Create a Game:**
   - Enter your name
   - Click "Create Game"
   - Share the generated game code with another player

2. **Join a Game:**
   - Enter your name
   - Enter the game code provided by the game creator
   - Click "Join"

3. **Setup Your Grid:**
   - Click cells in your preferred order to place numbers 1-25
   - Submit your grid when complete
   - Wait for the other player to finish setup

4. **Play the Game:**
   - Take turns selecting numbers from the pool
   - Numbers are automatically marked on both players' grids
   - First player to complete a row, column, or diagonal wins!

### Game Rules
- 5x5 Bingo grid
- Players arrange numbers 1-25 in any order they choose
- Win conditions: Complete any row, column, or diagonal
- Turn-based number selection from a shared pool

# 🏦 FinPath AI

**Regulatory-Aware Financial Navigation System with RAG-Powered Chatbot**

FinPath AI simplifies complex banking and financial processes into clear, structured, step-by-step guidance. It is powered by a Retrieval-Augmented Generation (RAG) pipeline using FAISS vector search and Llama 3 via Groq.

---

## Features

- **RAG Pipeline** — Retrieves relevant knowledge chunks from locally stored financial process documents using FAISS + Sentence Transformers.
- **Structured Responses** — Every answer follows a consistent format: Overview, Step-by-Step Process, Required Documents, Eligibility, Timeline, and Common Mistakes.
- **Context-Grounded** — Responses are based ONLY on the retrieved knowledge base. No hallucination.
- **Streaming Chat** — Real-time token streaming for a responsive chat experience.
- **Product-Aware** — Users select a financial product (Savings Account, Personal Loan, KYC) to scope their queries.
- **Profile-Aware** — Supports Salaried, Self-Employed, and Student user profiles.
- **Suggested Actions** — Quick-action buttons for common follow-up queries.

This system calculates credit scores from transaction data WITHOUT storing or analyzing:

## 🔬 Behavioral Features Explained

1. **income_stability** (0-1): How consistent is income?
   - Calculated as: `1 / (1 + coefficient_of_variation)`
   - High = Predictable income (good)
   - Low = Irregular income (concerning)

2. **expense_volatility** (0-1+): How variable are expenses?
   - Calculated as: `std_dev(debits) / mean(debits)`
   - Low = Predictable spending (good)
   - High = Erratic spending (concerning)

3. **savings_discipline** (-1 to +1): Is balance growing or shrinking?
   - Calculated as: `slope of balance trend`
   - Positive = Growing savings (good)
   - Negative = Depleting funds (concerning)

4. **cashflow_health** (0-2+): Income vs expenses ratio
   - Calculated as: `total_credits / total_debits`
   - >1.5 = Strong surplus (good)
   - <1.1 = Barely breaking even (concerning)

5. **transaction_consistency** (0-1): How regular are transaction timings?
   - Calculated from: `time gaps between transactions`
   - High = Regular patterns (good)
   - Low = Irregular activity (neutral/concerning)

6. **liquidity_stress** (0-1): How often is balance low?
   - Calculated as: `frequency of balance < 20th percentile`
   - Low = Consistently liquid (good)
   - High = Frequent low-balance periods (concerning)

7. **spending_aggression** (0-1): How often are large debits made?
   - Calculated as: `frequency of debits > 80th percentile`
   - Low = Controlled spending (good)
   - High = Frequent large purchases (concerning)

## How It Works

### Algorithm Overview

The tool uses a sophisticated **texture synthesis** approach inspired by professional editing tools:

1. **Mask Detection**: Automatically calculates watermark position based on image resolution:
   - **Tier 1** (≤1024px): 48×48px watermark, 32px margin
   - **Tier 2** (>1024px): 96×96px watermark, 64px margin

2. **Onion Peel Healing**: Processes pixels from the boundary inward:
   - Identifies the boundary between known and unknown pixels
   - For each boundary pixel, searches surrounding area for best texture match
   - Uses **Sum of Squared Differences (SSD)** to find optimal patch
   - Iteratively fills the hole layer by layer

3. **Context-Aware Matching**:
   - 7×7 window context analysis
   - 80px search radius with directional bias (prefers left/top over right/bottom)
   - 40 random samples per pixel for optimal match
   - Penalizes out-of-bounds and masked regions

4. **Final Smoothing**: 3×3 Gaussian blur to eliminate pixel grain artifacts

### Technical Specifications

- **Language**: Vanilla JavaScript (ES6+)
- **Canvas API**: `getImageData`, `putImageData` for pixel manipulation
- **Data Structure**: `Uint8ClampedArray` for efficient RGBA manipulation
- **Complexity**: O(n × m × s) where n = mask pixels, m = iterations, s = samples per pixel

# IPA - Inventory Procurement & Approval System

A multi-role workflow application for managing procurement requests with a hierarchical approval process. Built with PHP and MySQL.

## 📋 Overview

The IPA system facilitates a three-tier approval workflow for inventory procurement requests:
- **DEO (Data Entry Operator)**: Creates and submits procurement requests
- **HOD (Head of Department)**: Reviews and approves/rejects requests from DEOs
- **Principal**: Final approval authority for requests

## ✨ Features

### User Management
- Secure user registration and authentication
- Role-based access control (DEO, HOD, Principal)
- Password hashing and session management

### Procurement Workflow
- **DEO Dashboard**: Create requests with multiple items and quantities
- **HOD Dashboard**: Review pending requests and approve/reject
- **Principal Dashboard**: Final approval of HOD-approved requests
- Status tracking: PENDING_HOD → PENDING_PRINCIPAL → APPROVED

### PDF Generation
- Automatic PDF generation for approved requests
- Professional formatting with request details
- Download and archive functionality

### Request Management
- View request details and status
- Track approval timeline
- Multi-item support in single request

## 🛠️ Tech Stack

- **Backend**: PHP 7.4+
- **Database**: MySQL 8.0+
- **Frontend**: HTML5, Bootstrap 5.3.2
- **PDF Library**: FPDF
- **Authentication**: Session-based with password hashing

## 🚀 Installation

### Prerequisites
- PHP 7.4 or higher
- MySQL 8.0 or higher
- Web server (Apache/Nginx)
- FPDF library

### Database Setup

1. Create the database and user:
```sql
CREATE DATABASE IF NOT EXISTS ipa_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'ipa_user'@'localhost' IDENTIFIED BY 'ipa_pass';
GRANT ALL PRIVILEGES ON ipa_db.* TO 'ipa_user'@'localhost';
FLUSH PRIVILEGES;
```

2. Import the schema:
```bash
mysql -u root -p ipa_db < sql
```

### Application Setup

1. Clone the repository:
```bash
git clone https://github.com/yourusername/IPA.git
cd IPA
```

2. Create `db.php` configuration file:
```php
<?php
$host = 'localhost';
$db = 'ipa_db';
$user = 'ipa_user';
$pass = 'ipa_pass';

try {
    $pdo = new PDO("mysql:host=$host;dbname=$db;charset=utf8mb4", $user, $pass);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    die("Database connection failed: " . $e->getMessage());
}
?>
```

3. Set up web server to point to the project directory

4. Ensure write permissions for PDF directory:
```bash
mkdir -p pdfs
chmod 755 pdfs
```

# 🎯 Resume Analyzer

**AI-powered dual-mode resume analyzer that provides personalized feedback for students and batch candidate screening for recruiters using Groq's Llama 3.3 model.**

## ✨ Features

### 🎓 Student Mode
- **Comprehensive Resume Analysis**: Upload your resume and get detailed feedback on grammar, certifications, career objectives, skills, and experience
- **ATS Compatibility Score**: Get a percentage score (0-100%) showing how well your resume passes Applicant Tracking Systems
- **Skill Gap Analysis**: Identify missing skills for your target role with personalized learning resources
- **Job Aspiration Matching**: Analyze how well your resume aligns with your career goals
- **PDF Report Generation**: Download professional analysis reports with Notion-inspired aesthetics
- **Analysis History**: View and manage your previous resume analyses

### 💼 Recruiter Mode
- **Batch Resume Processing**: Upload multiple resumes (up to 50) simultaneously
- **Job Description Matching**: Automatically compare candidates against job requirements
- **Smart Filtering**: Customizable pass threshold (50-95%) for candidate screening
- **Call/Don't Call Recommendations**: AI-powered FIT/NOT_FIT decisions with detailed reasoning
- **Three-Tab Results View**: Organize candidates into "Call for Interview", "Don't Call", and "All Candidates"
- **Candidate Comparison**: View detailed breakdowns of skills, experience, gaps, and suggestions
- **Bulk PDF Export**: Generate comprehensive recruiter reports for all analyzed candidates

### 🎨 Design
- **Notion Aesthetic**: Clean, minimalist interface inspired by Notion
- **Glassmorphism Effects**: Modern frosted-glass UI elements with backdrop-filter effects
- **Fully Responsive**: Works seamlessly on desktop, tablet, and mobile devices

